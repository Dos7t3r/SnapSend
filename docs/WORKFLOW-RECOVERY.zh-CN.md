# 0.6.2 发送流程与任务管理修补

2026-10-09，基于已安装的 iPad 归档原型继续修补。保留极光玻璃布局，优先解决 Mac 入口缺失、照片管理和打断恢复；本轮不是完整重做三端所有界面。

## 操作入口

- 侧边栏新增“发送任务”。可筛选全部、待发送、已发送、待处理；整行打开大图，右侧更多菜单独立响应。
- 每张图片的更多菜单：取消待发任务（保留原图）、导出原图、删除 Mac 原图。取消与删除都有明确提示；不会撤回 AI 聊天或删除手机/iPad 来源图。
- 已开始上传的任务先等待完成或核对，不能假装即时取消。正在发送的图片禁止删除；Chrome 发送另一张图时不阻止删除无关原图。原生附件测试期间暂禁止删除。
- “恢复当前队列与自动发送”继续已授权队列和新课堂图；“开启自动发送”仍只处理之后的新照片。仅保存、已取消、私人照片不会因为恢复而排队。

## 打断与恢复

草稿在扩展检查后、附图前出现，会返回明确的 deferred 回执，Mac 将 preparing 退回 queued，保持同一 UUID。这个退回只适用于扩展证明没有附图的路径；已经附图或提交后无法确认的结果仍是 uncertain，需要人工核对，不能盲目重发。

输入框有草稿或 AI 回答中，扩展退避检查；草稿发送/清空、回答结束后继续。长回答可在扩展主动点击“停止当前回答并继续”。等待时不抢焦点。聊天切换或关闭时提示回到目标；“查看绑定聊天”可明确打开保存的目标。正常等待不要求刷新页面。

原上传最长可到 60 秒，但 Mac 原先在 45 秒没有普通心跳时就停自动发送。现在持有活动的照片/提示词投递时不会按空闲心跳误判；投递自身的超时仍保留。安装新版扩展后需要一次刷新注入新脚本，之后的正常打断不依赖刷新。

核对完成后，输入框里若还有附件，先由用户发送或移除，再恢复。扩展不删除用户草稿/附件、不自动把 uncertain 当成未发送。

## iPad 一次性授权

分享面板把本次导入图片默认选中，旧待传图片默认不选。列表可逐张勾选，按钮明确显示选中数量。选择“发送这 N 张到 AI”授权这一批；“仅保存这 N 张到 Mac”不授权 AI。仅支持新版 Mac 明确声明能力、当前课堂存在且已绑定聊天时显示发送按钮。

传输前原子保存每个选中 UUID 的授权和课堂，断线不会把图片悄悄改投新课堂。Mac 在接收处再次校验课堂/绑定，变化时仅保存并提示检查。单次分享不打开持续自动发送；未勾选图片不传输。Mac 保存回执后关闭面板，电脑继续 AI 队列，不等待回答。

USB 回执丢失重试不会重发已发送任务，也不会把用户在 Mac 已取消的任务恢复。对于已有归档的 held 图片，本次重试即便声明发送也保持 held；需在 Mac 明确手动选择发送，优先避免重复或违背取消。

旧 Mac 不声明能力时，新 iPad 只允许保存；旧 iPad 不声明能力时，新 Mac 不发送新 FEATURES 指令。iPhone 原有可选发送字段仍兼容。

## 资源控制

不添加常驻轮询、动画计时器、相册扫描或图片全尺寸解码。浏览器沿用有界检查与等待退避。iPad 用原文件、480px 单图预览、256KB 串行分块、20MB/张与 100MB 待传预算；仅分享面板可见时监听，关闭释放连接和任务。新增授权/勾选是少量元数据，Mac 接收仍保留一张有界完整图缓冲。

这些是实现限制，不是本轮实测续航结论。课堂连续使用的能耗和大图内存仍需真机观察，不能把构建/模拟器 CPU 当成 App 耗电。

## 实际验证

- 浏览器：49 项全部通过，包括草稿领取竞争、等待回答恢复、待核对附件锁、单次授权、队列恢复入口与错误聊天拒绝。
- 核心：29 项全部通过，包括取消原子性、活动任务拒绝取消、仅保存持久化与文件归档。
- iPad：9 项全部通过，包括真实 NSItemProvider → 认证 → 分块传输 → 保存回执；明确 AI 授权只发送本次图片、旧图未选中、保存回执后无需 AI 返回、计划冻结/重载与无课堂拒绝授权、多图传输中途断线不会误报完成。
- Mac 隔离模型：已运行并验证 deferred 同 UUID 重试、长上传心跳、核对后恢复、取消保留原图、iPad 目标变化仅保存、重复帧不撤销取消、活动图删除阻止与无关图可删除。
- Mac 界面：最终 16 种状态渲染完成；960×640 下的概览、任务、收件箱和课程列表滚动检查通过。任务页使用整页滚动，避免列表覆盖操作说明。
- 三端编译：Mac Release、iPad 签名 Release、iPhone 模拟器 Release 均通过。包含最新多图断线修补的 iPad 真机覆盖安装及主 App 启动成功；最终 Mac App 已重新打开。
- Mac 启动后短时单次快照约 0.3% CPU、75MB RSS。仅为空闲观察，不代表整节课的能耗。

早期受限环境未能访问模拟器服务和 SwiftUI 宏插件；切换到授权的本机检查后重新执行，未修改代码屏蔽这些错误。一次界面渲染编译期间更新了测试源，Swift 拒绝该次构建；已安排最终代码重新运行。

## 需要用户真机确认

1. Mac 与 Chrome 都更新后，排队两张课堂图，手动发一句消息。回答结束后应继续投递，不用刷新；有草稿时等待，内容不会被覆盖。
2. 对待发图点取消，恢复队列后该图保持“仅保存”。单独删除 Mac 原图后 Mac 图库消失，手机/iPad 来源图仍存在。
3. iPad 留一张未传副本，再分享一张新截图。旧图默认未勾选；发送按钮数量只包含新图。点仅保存不发 AI，点发送由 Mac 继续；如果改变课堂导致拒绝，提示已保存并检查 Mac。
4. 连续五张、传输中拔线、反复关闭分享面板和课堂长时间能耗，还需实测。

原生桌面 AI 仍缺少可靠送达回执，点击发送后要求核对；这轮不宣称 Codex 原生适配已完成，也不使用猜测坐标发送。iPhone 视觉本轮未另做重构，检查共享协议编译兼容。
