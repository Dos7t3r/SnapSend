# 开发历史记录

以下是首次公开发布前的开发笔记，保留当时版本的行为和验证结果；当前安装步骤与状态请以根目录 README 和 CHANGELOG 为准。

# SnapSend

纯 USB 课堂拍照助手。手机确认照片后自动传到 Mac，按课程与每次上课归档。已加入 ChatGPT 网页投递扩展与原生 App 兼容性验证入口；实发兼容性仍需验证。

## 新版用法

1. 退出旧版 Mac SnapSend，打开 build/SnapSend.app。手机和 Mac 必须同时更新到新版。
2. Mac 左下角“新建课程”：填写名字，自动创建第一节课并记录 Mac 本地时间。
3. 插线、解锁手机并保持 SnapSend 前台，Mac 点击“连接 iPhone”。
4. 首次手机显示 6 位一次性验证码，Mac 输入并点击“配对并记住设备”。验证码 60 秒有效，错误尝试最多 3 次。以后点击连接即可自动验证，无需再输入。
5. 手机“上课”页显示当前课程与课堂时间。拍照确认后，照片保留拍摄时的课堂标识，自动传到对应课堂。
6. 同一课程下用“课程 → 开始新一节课”继续下一次上课。浏览旧课堂不会改变正在拍摄的课堂；如要继续旧课，选“将此节课设为当前课堂”。

## 课程与历史

- 侧栏按“课程 → 每次上课”显示照片数量、Mac 本地日期和时间。
- 搜索课程名或日期（例如 2026-10-07）。
- 可以重命名课程、结束课堂、继续旧课堂，在 Mac 查看大图与缩略图。
- 新照片物理归档在 Courses/<课程 ID>/<课堂 ID>/ 中，UI 显示自定义名字和时间。
- 旧照片自动归入“历史照片”，保留原文件，不搬移或删除。
- 原图归档在 ~/Library/Application Support/SnapSend/Prototype。

## 手机功能

- 上课 / 历史 / 设置三个页面。
- 课堂自动同步、断线后仍能记录上次课堂，重连按原课堂归档。
- 历史按课程与每次上课分组，可切换待传队列。
- 点照片后支持双指缩放，菜单提供导出原图与重新传输。
- 清晰 / 快速 JPEG 档位，设置会记住。
- 可以忘记配对电脑；这不会删除任何照片。
- Mac 接收确认后手机仍保留照片，重启后历史与状态恢复。

## 配对与传输

USB 服务和代理均只监听回环地址，iproxy 使用 -l USB 模式，不开个人热点。
短验证码只用于首次授权，长期随机凭据保存在两端钥匙串。已配对设备每次连接使用新的 HMAC 挑战，不再次输入验证码。
当前传输仍是 USB 回环内的应用帧，尚未加入媒体帧认证加密和按字节断点续传。未确认照片重连整张重传，Mac 按 photoID 去重。
本版本协议 v2 与旧版长密钥协议不兼容，必须更新两端。

## Chrome 自动投递（v0.2）

本轮仅更新 Mac，现有 v2 手机 App 不需要重装。网页入口先支持 chatgpt.com，其他 AI 尚未适配。

1. 退出旧 Mac SnapSend，打开 build/SnapSend.app。选择或开始当前课堂。
2. AI 自动投递选择 Chrome。复制课堂提示词，在 Chrome 的本课专用聊天里发送一次。
3. Mac 点“安装浏览器桥接并打开扩展文件夹”。桥接注册仅允许随包扩展的固定 ID。扩展目录路径自动复制。
4. Chrome 地址栏打开 chrome://extensions；打开开发者模式 → 加载已解压的扩展程序。在文件夹选择框按 ⌘⇧G，粘贴路径，回车并选择。新装后刷新 ChatGPT 页面；更新后在扩展页点重新加载。
5. 打开已有聊天（URL 必须含 /c/），点击扩展图标 → 绑定当前聊天。Mac 会显示绑定地址与课堂。
6. 回 Mac 开启自动发送，然后回到绑定的 Chrome 标签页，保持在前台。手机确认拍照后，Mac 原图先落盘，扩展上传最大边 2048px 的 JPEG 副本，观察附件就绪后发送，并检查网页中出现带图片的新用户消息。
7. 有草稿、旧附件、AI 正在回答或 Chrome 不在前台时等待。切换课堂后需重新绑定。重启 Mac/Chrome 后不会自行恢复发送，需重新绑定并开启。
8. 结果不确定时，在 Mac 选中照片并到 AI 核对。已存在消息则点“AI 已收到”；未发送则删除草稿附件后点“重新排队”。随后刷新聊天页，再开启自动发送。
9. 下课先暂停投递，核对本课队列全部完成，再在 AI 输入“下课总结”。总结当前仍是手动触发。

扩展不会读取其他网站；只有 ChatGPT 域名权限。手机到 Mac、Mac 到扩展均走本机链路，AI 网页上传仍使用 AI 的网络连接。网页 DOM 适配可能随 ChatGPT 改版失效；无法确认状态时暂停，不能承诺服务器侧 exactly-once。网页消息出现只说明页面确认提交，不代表 AI 已完整理解内容。

原生入口目前只适配 com.openai.chat（本机 ChatGPT Classic.app）。需要辅助功能权限、带可区分标题的聊天窗口、AX 暴露附件与发送按钮。先做“不发送”的附件测试；提交后由于无法可靠验证原生回执会暂停核对。com.openai.codex 对应的应用不视作原生 ChatGPT 适配目标。当前两条路径均未完成此机器的真实 AI 发图验收，原生全自动连续投递尚未完成。

桥接采用 Chrome Native Messaging（stdio 32 位长度 + JSON），宿主转到 Mac 的 127.0.0.1:27184 HTTP 服务。服务使用随机 token，token 文件权限 0600，不开放 LAN 监听，不提供 CORS。照片副本限制为 680KB，保证宿主到扩展单条消息低于 1MB。原始 USB 照片不受该压缩影响。扩展只绑定一个明确聊天标签页与 URL；课堂与照片投递状态由 Mac 进程单独写入。

本机 Native Messaging 桥接已注册，首次只需加载扩展；应用移动位置后请重新安装桥接。

测试：Swift 核心测试 8 项；node --test Tests/Browser/*.test.cjs 共 10 项。真实回环/stdio 集成测试也通过（模拟照片副本，验证 token 门禁、0600 权限、连续两帧与最大响应）。浏览器测试使用模拟 DOM 和 Chrome API，尚不等价于实际 ChatGPT 网页兼容性验证。


## v0.3 体验修复

- 手机同一课堂照片改为全屏相册：左右分页、前后按钮、张数和当前照片时间/传输状态；双击与双指缩放，缩放后拖动查看。导出/重传操作跟随当前照片。只加载当前页与相邻页的大图，避免整课图片同时解码。
- Mac 顶部显示 USB、课堂归档与 AI 投递三个状态卡，明确当前下一步；投递控制置于照片之前，详细安装教程可折叠。Chrome 心跳丢失时暂停自动发送。
- Chrome 弹窗每 1.5 秒检查连接，逐项显示 Mac、课堂、USB、网页、绑定和自动发送状态。主按钮跟随状态变为绑定/开启/暂停/刷新，支持直接在扩展开启或暂停，不必往返 Mac。工具栏角标显示 ON/OFF/!。
- 修复弹窗夺取焦点造成无法绑定的错误：绑定/检查忽略弹窗焦点，实际附加与发送仍要求聊天在前台。
- 更新：退出旧 Mac App 并打开 build/SnapSend.app；在 chrome://extensions 重新加载 SnapSend，然后刷新 ChatGPT 页面。沿用同一扩展 ID，不必卸载或重新加载文件夹。手机通过同一 bundle ID 覆盖安装，照片保留。
- 本轮浏览器模拟测试 15 项通过；已检查真实 ChatGPT 页面存在当前适配的输入框、form/composer 与 image/* 上传入口。真实发图与手机滑动手感仍需用户验收。浏览器安全策略禁止自动进入 chrome://extensions，重新加载必须由用户完成。

真实页面检查进一步确认当前 composer 使用 accept 未限制的通用上传入口，图片专用入口在 composer 之外；扩展优先当前 composer 文件入口，避免误选其他上传控件。

## v0.3.1 项目聊天地址修复

Mac 与扩展均支持 /c/<对话> 和 /g/<项目或 GPT>/c/<对话>，拒绝没有对话的项目首页。仍然按绑定的完整 URL 检查目标，切换另一对话不会自动投递。更新后重启 Mac App，重新加载扩展并刷新聊天页，再重新绑定。


## v0.3.2 项目新版页面适配

真实项目页面的输入框没有 prompt-textarea ID，使用 form 内带 ChatGPT 标签的 contenteditable/role=textbox。扩展现在兼容两种结构，并适配新布局的“停止”按钮与用户消息语义标题。发送回执同时检查新用户图片消息与输入区附件已清空，不因加载更早历史消息增加数量而确认成功。未识别输入框时主面板给出具体修复状态，不再引导用户反复点击绑定。真实页面只读验证成功识别唯一可见输入框、附件区域和用户图片消息；尚未执行实际发送验证。更新只需要重新加载扩展并刷新聊天页，手机和 Mac 进程不用重启。


## 手机相册黑屏与翻页修复

将照片列表与选中项合并为单个 PhotoGallerySelection，避免首次展示读取到空列表。图片控件通过明确的容器尺寸布局，读取失败显示恢复提示。照片分页改为 UIKit UIPageViewController，复用当前与相邻图片页；完成翻页后才更新选择，普通 SwiftUI 状态刷新不重建当前页。缩放时暂停外层翻页，恢复原比例后重新允许翻页，双击与双指缩放保留。原图与照片记录不迁移、不删除。

新增 GalleryTests 模拟器测试目标（使用 SnapSendPhone 应用宿主）。三项测试通过：零尺寸初始化后图片布局与缩放/旋转恢复；失败提示可见；SwiftUI 容器下真实像素渲染及界面刷新保留同一个图片页和缩放。测试用生成的红色图片，不访问用户课堂照片。首轮无宿主测试启动受阻已停止，最终应用宿主测试完成且全部通过。最终原生分页版已覆盖安装至原 bundle ID。翻页手感仍以真机体验为准。


## v0.4.0 全新现代化重构与全链路追踪

### 1. USB 拔线自动重连 (Zero-Click Auto Reconnect)
- 拔掉数据线或 iPhone 临时离开后，重新插线**无需再次手动点击“连接 iPhone”**。
- Mac 端内置智能感应轮询器，自动重新连接并完成钥匙串 HMAC 认证；若用户手动点击“断开连接”，则会礼貌停止自动尝试。

### 2. Mac App UI 全新重构与告警通知
- **现代原生的分区布局**：彻底重构旧版堆砌冗长文本的界面，划分为：
  - **侧边栏 (Sidebar)**：版本号 Badge (`v0.4.0`)、课程搜索、课程与课堂两级树状列表、快捷新建课程。
  - **顶部 HUD 状态卡片**：USB 连接状态（实时连接模式与自动重连指示）、当前课堂信息、AI 自动投递通道（通道切换、自动开关、绑定目标与心跳）。
  - **全链路动态告警与系统通知**：发生断开、浏览器心跳中断或投递失败时，顶部自动出现警示横幅并派发 macOS 原生通知。
  - **照片列表与去向 Badge**：照片缩略图带状态角标；右侧点击呼出独立 Inspector 详情抽屉，展示 4 步流转时间轴与快捷核对操作。
  - **弹窗式设置与教程**：将长篇教程与安装引导收纳至“投递设置与指引”弹窗，主界面保持极致清爽。

### 3. 手机端全链路照片去向追踪
- 新增 `STATUS` 双向同步协议。手机不仅记录“Mac 已接收”，更能实时了解照片在下游的去向：
  - 💻 `Mac 已归档`
  - ⏳ `等待投递 AI`
  - 🚀 `AI 投递中`
  - 🤖 `AI 已成功接收`
  - ⚠️ `需人工核对`
- 手机端相册列表彩色角标与全屏查看器顶部状态栏同步更新，重连时自动同步状态。

### 4. Chrome 自动投递免手动点击聚焦
- 彻底修复必须手动点击 Chrome 窗口才能触发发送的问题。
- 移除 `content.js` 与 `worker.js` 对 `document.hasFocus()` 的强依赖限制；投递时自动激活绑定的 ChatGPT 标签页与窗口前台，支持全自动后台触发发送。

### 5. 版本号管理机制
- 建立统一版本号标准，当前版本锚定为 `v0.4.0`（包含 Mac App、Core 协议、Chrome 扩展及编译脚本），后续所有变更严格递增维护版本号。


## v0.4.1 彻底解决抢焦点与纯静默后台投递

### 1. 彻底禁用 macOS 系统窗口焦点抢占
- 移除了扩展中的 `chrome.windows.update(..., { focused: true })` 调用。任何情况下 Chrome 扩展**绝对不再抢占操作系统窗口焦点**，保证用户在任何其他软件中正常打字、办公不受任何干扰。

### 2. 自动发送暂停或无照片时完全休眠
- 扩展中的后台心跳 `tick()` 加入严格门禁：
  - 当在 Mac 端**关闭“自动发送”**或存在待核对照片时，扩展立即返回，**完全不操作任何页面、标签页或窗口**。
  - 当课堂队列中**无待发照片**时，扩展保持静默等待，不打扰浏览器。

### 3. 支持真正的纯后台静默投递
- `content.js` 移除了页面可见性 (`visibilityState === 'hidden'`) 的阻断，Chrome 无论是最小化、处于后台窗口还是切至其他标签页，均可直接在后台完成附件挂载和点击发送，实现真正的静默投递。


## v0.5.0 UI 与课堂流程（下方视觉说明为历史版本）

### 1. USB 桥接重连
- **退避重连**：只停止和重启 SnapSend 自己的 `iproxy`。断线后按 3、6、12、24、48、60 秒间隔重试，成功连接后重置；不会杀掉其他程序。端口被其他程序占用时，请在设置更换本地端口。
- **手动重连**：设置中“立即重连”可重新启动桥接。

### 2. 现代拟态液态玻璃风格 UI (Liquid Glass Morphism)
- **高级质感与光影**：全面应用 SwiftUI 深度毛玻璃材质 (`.ultraThinMaterial`)、流体多层光泽渐变描边、状态环境微光光晕 (Ambient Glow)。
- **彻底解决窗口缩放截断 Bug**：
  - 顶部 HUD 状态卡片重构为响应式流式布局 (`LazyVGrid(columns: [GridItem(.adaptive(minimum: 280))])`)，在任意窗口尺寸下均自适应折行换列，杜绝字段挤压和截断。
  - 主窗口施加最小尺寸保护 (`1040 × 680`)，保证所有分区层次井然有序。

### 3. 开课 Prompt 自定义保存与全自动下发联动
- **提示词自定义与持久化**：开课提示词与下课总结支持自定义编辑与实时持久化保存，并提供“恢复默认预设”按钮。
- **一键开课全自动联动**：开启“点击开始上课时，自动连接 AI 并在会话中发送开课提示词”后，用户只需在手机选择对应课程，点击“开始上课”，Mac 将自动通过 Chrome 扩展将 Prompt 注入当前 ChatGPT 对话并提交，用户即可直接拍照发图。

### 4. 照片批量编辑与单图直发 AI
- **悬浮拟态玻璃胶囊控制台 (Floating Capsule Bar)**：
  - 支持多选模式：提供“全选 / 取消全选”、“批量发送 AI 🚀”、“批量导出原图”以及“批量删除”。
- **单图直发 AI**：
  - 每张照片卡片悬浮 Hover 即刻展示“发给 AI”胶囊按钮。
  - 右键 Context Menu 快捷直达“🚀 发送给 AI”。
  - 右侧 Inspector 抽屉提供显目的拟态发光直发按钮。

### 5. 本地存储、缓存管理与重构设置面板
- **四维层级清晰分区**：
  1. **课堂与 Prompt**：开课提示词与总结配置、自动联动开关、即时下发与复制。
  2. **AI 投递通道**：Chrome 扩展与原生客户端配置、一键安装本地桥接、快捷管理页。
  3. **本地存储与缓存**：存储容量与图片总数实时统计、一键安全清理临时投递缓存、异常队列一键重置。
  4. **USB 与自愈诊断**：端口配置、Zero-Click 自动重连开关、桥接重连与忘记设备。
